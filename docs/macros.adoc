= sysml-publish AsciiDoc macros

These macros can be used in the AsciiDoc textual representations of a model
(`rep language "asciidoc" /* ... */`). They are replaced when the page is
built. Every macro name starts with `sysml-`.

"The page's element" is the element whose page is being built. A
representation inherited from a definition is shown on the page of each usage
typed by it, so there the page's element is the usage, not the definition.

[[naming]]
== Naming elements

Macros that take an element (`sysml-members-list`, `sysml-metadata-table`)
read its name the way a SysML reference is read, trying in turn:

. a qualified name from the top of the model: `Vehicles::Wheel`;
. a name inside the page's element, then inside each element around it,
  outward: `wheels`, or `pd::wheels` from the page of a sibling of `pd`;
. the qualified name of a standard-library element the model uses:
  `ScalarValues::Real`;
. a plain name that only one element in the model has: `Wheel`.

Every segment may be the element's name or its short name, quoted or not:
for `package <V> Vehicles { part def <W> Wheel; }`, `Vehicles::Wheel`,
`V::W`, `V::Wheel` and `W` all name the wheel. A name that several elements
answer to in the same step fails the macro, asking for a qualified name; a
name nothing answers to fails it too (<<failures>>).

[[failures]]
== When a macro fails

A macro that cannot do what is written, such as one naming an element the
model does not have, does not stop the run. In its place the page shows a
placeholder with the macro and the problem, marked with the class
`sysml-failed`:

[source,sysml]
.model/parts.sysml
----
package Model {
    part def pd {
        attribute mass = 5;
        rep language "adoc"
            /* Mass: sysml-value:mas[]. */
    }
}
----

shows on the page of `pd`:

====
Mass: [.sysml-failed]#sysml-value:mas[]: opensysml: Evaluate: evaluation
failed: unresolved reference: mas — did you mean mass?#.
====

The run also reports a warning with the file and line where the macro is
written, the page, the macro and the problem:

----
level=WARN msg="model/parts.sysml:5: Model::pd: sysml-value:mas[]: opensysml: Evaluate: evaluation failed: unresolved reference: mas — did you mean mass?"
----

A block macro (`sysml-doc::Nothing[]`) leaves a block in its place.

The rest of the page is built as usual, and every failing macro on every
page is reported, each once per page. A representation inherited by several
usages reports its failing macro on each of their pages. The run still
succeeds; check the warnings to find the problems.

== sysml-name

Inline macro. Replaced by an element's name, as declared and without quotes.

* `sysml-name:[]` gives the name of the page's element. An element without
  a name gives `Unnamed`.
* `sysml-name:<element>[]` gives the name of the element the target names,
  read as described in <<naming>>: `sysml-name:Model::AircraftPart[]`,
  `sysml-name:ap[]` (a short name), `sysml-name:Pump::'rated power'[]` (a
  quoted name, which may contain spaces). A target that names no element,
  or several, fails the macro (<<failures>>).
* `sysml-name:@<metadata>[]` and `sysml-name:@<metadata>::<attribute>[]`
  give the name of metadata applied to the page's element, and of one of its
  attributes. Put an element before the `@` for metadata on another element:
  `sysml-name:wing::@m::owner[]`. The metadata is named by its metadata
  def's name or short name. The element must carry that metadata, and the
  attribute must be one of the def's or its supertypes'; otherwise the run
  stops with an error.
+
For `part wing : ap { @m { owner = "Petr"; } }`, on `wing`'s page
`sysml-name:@m[]` gives `m` and `sysml-name:@m::owner[]` gives `owner`. To
show the attributes' values, use `sysml-metadata-table::m[]`.

[[name-links]]
When the element has a page, the name links to it: on the page of `a<b`,
`sysml-name:pd[]` is a link to the page of `pd`. An element without a page,
and the page's own element, give plain text. `sysml-short-name` and
`sysml-qualified-name` link the same way. In a document title the link
shows in the page heading; the browser tab and the sidebar show the text
only.

It gives the element's name, not the page title, so it can be used in a
document title: `= Element: sysml-name:[]` titles each page showing the
representation with that page's element.

Syntax:: `sysml-name:[]`, `sysml-name:<element>[]`,
`sysml-name:[<element>::]@<metadata>[::<attribute>][]`
Attributes:: none

Example:

[source,sysml]
----
part def Pump {
    rep language "asciidoc"
        /* The sysml-name:[] pump moves coolant. */
}
part mainPump : Pump;
----

The page of `Pump` reads "The Pump pump moves coolant." The page of
`mainPump` reads "The mainPump pump moves coolant."

== sysml-rep

Inline macro. Replaced by the body of an element's textual representation
in another language than AsciiDoc: a formula in LaTeX, a constraint in OCL,
a snippet of code.

* `sysml-rep:[<language>]` gives the representation in that language that
  the page's element owns.
* `sysml-rep:<element>[<language>]` gives the one the named element owns.
  The element is read as for `sysml-name`, see <<naming>>: qualified or
  relative names, short names, quoted names, and
  `[<element>::]@<metadata>[::<attribute>]`.

The language is compared in any letter case and may be quoted:
`sysml-rep:["python"]`. If the element owns several representations in the
language, they are joined in the order they are declared. Only the
element's own representations count, not inherited ones. The body is
inserted as plain text: it is escaped and not read as AsciiDoc.

A missing language, or an element without a representation in it, fails the macro (<<failures>>).

Representations in other languages are still reported by the warning
"skipped representation in language ...", since they get no page of their
own.

Syntax:: `sysml-rep:[<language>]`, `sysml-rep:<element>[<language>]`
Attributes:: the language, first and only positional attribute

Example:

[source,sysml]
----
part def Engine {
    rep language "asciidoc"
        /*
        Power: `sysml-rep:[python]`
        */
    rep language "python"
        /* power = torque * speed */
}
----

The page of `Engine` reads "Power: `power = torque * speed`", the backquotes
setting it in a monospace font.

== sysml-qualified-name

Inline macro. Replaced by the qualified name of the page's element, written as
SysML writes it: `Model::pd`, or `Model::'my part'` for a quoted name. An
element without a qualified name, such as an unnamed one, gives its positional
name, like `Model::@2`.

With a target, it gives the qualified name of the element the target names,
read as for `sysml-name` (see <<naming>>): `sysml-qualified-name:ap[]` gives
`Model::AircraftPart`. It links to the element's page when it has one, as
`sysml-name` does (see <<name-links>>).

Syntax:: `sysml-qualified-name:[]`, `sysml-qualified-name:<element>[]`
Attributes:: none

Example: `Defined as sysml-qualified-name:[].` on the page of `mainPump` in
package `Plant` reads "Defined as Plant::mainPump."

== sysml-doc

Block macro, on a line of its own. Replaced by the `doc` comments of the page's
element, in the order they are declared, each parsed as AsciiDoc, so markup in
a `doc` works. An element without a `doc` gives nothing.

Only the page's element's own `doc` comments are used: in a representation
inherited from `Pump`, it shows the doc of `mainPump` on `mainPump`'s page, not
the doc of `Pump`.

With a target, it shows the `doc` comments of the element the target names,
read as for `sysml-name` (see <<naming>>), whether that element has a page or
not: `sysml-doc::engine[]`. Macros inside those comments still describe the
page's element, not the named one.

The documentation is placed in an open block with the role `sysml-doc`, for
styling.

Syntax:: `sysml-doc::[]`, `sysml-doc::<element>[]`
Attributes:: none

Example:

[source,sysml]
----
part def Pump {
    rep language "asciidoc"
        /*
        = sysml-name:[]

        sysml-doc::[]
        */
}
part mainPump : Pump {
    doc /* The *main* coolant pump. */
}
----

The page of `mainPump` shows "The main coolant pump.", with "main" in bold.

== sysml-short-name

Inline macro. Replaced by the short name of the page's element: `P-101` for
`part <'P-101'> mainPump`. An element without a short name gives nothing, so
the macro disappears.

With a target, it gives the short name of the element the target names, read
as for `sysml-name` (see <<naming>>): `sysml-short-name:AircraftPart[]` gives
`ap`. It links to the element's page when it has one, as `sysml-name`
does (see <<name-links>>).

Syntax:: `sysml-short-name:[]`, `sysml-short-name:<element>[]`
Attributes:: none

Example: `Tag: sysml-short-name:[]` on the page of `part <a> aaaa` reads
"Tag: a".

== sysml-members-list

Block macro, on a line of its own. Replaced by a bullet list of the members the
page's element owns, in the order they are declared: its parts, ports,
attributes and so on. Each item is the member's name, `Unnamed` for one without
a name, and links to the member's page when it has one. Annotations are left
out: `doc` comments, comments, representations and metadata such as `@tag`.
Inherited members are not listed.

* Without an element, `sysml-members-list::[]` lists every member, followed by
  its types in parentheses when it has any: `inlet (FluidPort)`,
  `both (Wheel, Sport)`. A member that gets its type from what it subsets or
  redefines shows that type too: `part front :> wheels;` gives `front (Wheel)`.
* With an element, `sysml-members-list::Wheel[]` lists only the members that
  are typed by it, subclass it or subset it (`part w : Wheel;`,
  `part def Racing :> Wheel;`, `part front :> wheels;`, a redefinition),
  directly or through a chain (`part spare : Sport;` with `Sport :> Wheel`),
  without their types. The element is named as described in
  <<naming>>, short names included.
* With an element kind, `sysml-members-list::partUsage[]` lists only the
  members of that kind, without their types. A kind is a SysML metaclass
  name, in any letter case: `partUsage`, `PortUsage`, `interfaceUsage`,
  `attributeUsage`, `partDefinition`, `actionUsage` and so on. The kind
  must match exactly: interfaces are not listed as `partUsage`, although
  SysML counts an interface as a kind of part.

A target is read as an element first; only when no element has that name is
it read as a kind. A name that is neither fails the macro (<<failures>>), and
so does a name several elements have.

An empty list gives nothing: the macro line is dropped. The list has the role
`sysml-members-list`, for styling.

Syntax:: `sysml-members-list::[]`, `sysml-members-list::<element>[]`,
`sysml-members-list::<kind>[]`
Attributes:: none

Example:

[source,sysml]
----
part def Wheel;
part def Sport :> Wheel;
part def Pump {
    rep language "asciidoc"
        /*
        = sysml-name:[]

        sysml-members-list::[]

        Wheels:

        sysml-members-list::Wheel[]
        */
    port inlet : FluidPort;
    attribute flowRate : Real;
    part spare : Wheel;
    part def Racing :> Sport;
}
----

The page of `Pump` lists inlet (FluidPort), flowRate (Real), spare (Wheel) and
Racing; under "Wheels:" it lists spare and Racing: `spare` is typed by
`Wheel`, `Racing` specializes it through `Sport`.

== sysml-iface-ends

Block macro, on a line of its own. Replaced by a bullet list of the ends of an
interface, or of any connection: the page's element with
`sysml-iface-ends::[]`, or the element a target names
(`sysml-iface-ends::airDuct[]`), named as described in <<naming>>.

Each item is the end's name and the feature it connects, the segments of the
feature linked to their pages when they have one: `source: engine.air`.

* `connect a to b` and `connect (a, b)` give ends named `source` and
  `target`.
* Ends named by an interface def keep its names: `supplier: x.p`.
* The unnamed ends of an n-ary `connect (a, b, c)` show the feature only.
* The ends of an interface def connect nothing, so they show their names
  only.

The source end comes first, then the other ends in the order they are
declared. An element without ends fails the macro (<<failures>>). The list has the role `sysml-iface-ends`, for styling.

The attribute `depth` chooses how much of the connected feature's path is
shown. Its path is the qualified name of the part it is on followed by the
feature: `Model::aircraft::engine::air`. `depth` keeps that many segments
from the end, joined by `::`; `all` keeps the whole path. Every segment
whose element has a page is a link.

[cols="1,2"]
|===
|Written |Item

|`sysml-iface-ends::airDuct[]` |`source: engine.air` (the chain as written)
|`sysml-iface-ends::airDuct[depth=1]` |`source: air`
|`sysml-iface-ends::airDuct[depth=2]` |`source: engine::air`
|`sysml-iface-ends::airDuct[depth=3]` |`source: aircraft::engine::air`
|`sysml-iface-ends::airDuct[depth=all]` |`source: Model::aircraft::engine::air`
|===

`[2]` is the same as `[depth=2]`. A depth longer than the path shows the
whole path. Names that need quotes are quoted, as in a qualified name:
`wing::'de-icing fluid'`. A depth that is neither a positive number nor
`all` fails the macro (<<failures>>).

Syntax:: `sysml-iface-ends::[]`, `sysml-iface-ends::<element>[]`,
`sysml-iface-ends::<element>[depth=<n>|all]`
Attributes:: `depth` (also the first positional attribute): a positive
number or `all`

Example:

[source,sysml]
----
part aircraft {
    rep language "asciidoc"
        /*
        Air duct:

        sysml-iface-ends::airDuct[]
        */
    part engine { out port air; }
    part airConditioner { in port air; }
    interface airDuct connect engine.air to airConditioner.air;
}
----

The page of `aircraft` lists source: engine.air and target:
airConditioner.air.

== sysml-metadata-table

Block macro, on a line of its own. Replaced by a table of the attributes of
the named metadata on the page's element, one row per attribute with its name
and value. The table is titled with the metadata def's name.

* The value is the one the element binds, as in `@Info { owner = "pete"; }`.
* Where the element binds none, it is the value the metadata def gives: a
  default (`attribute count : Integer default 3;`) or a fixed value
  (`attribute ratio : Real = 0.5;`).
* Where neither exists, the value is `(no value)`.
* Strings are shown without quotes. Other values are shown as written in the
  model: `7`, `true`, `Level::low`, `1 + 2`. Expressions are not evaluated.
* Attributes of the metadata def's supertypes are included, after its own.
* Both `@Info` in the element's body and the prefix form `#Info part x;` count.
* An element without that metadata gives nothing. If it carries the metadata
  twice, there is one table each.

The tables are placed in an open block with the role `sysml-metadata-table`,
for styling.

Syntax:: `sysml-metadata-table::<metadata def>[]`, where the metadata def is
named as described in <<naming>>, among metadata defs only: by qualified name
(`sysml-metadata-table::Plant::Info[]`), by a name relative to the page's
element, by short name, or by its name when no other metadata def has it
(`sysml-metadata-table::Info[]`)
Attributes:: none

A missing, unknown or ambiguous metadata def name fails the macro (<<failures>>).

Example:

[source,sysml]
----
metadata def Info {
    attribute owner : String default "nobody";
    attribute count : Integer default 3;
}
part def Pump {
    rep language "asciidoc"
        /*
        = sysml-name:[]

        sysml-metadata-table::Info[]
        */
}
part mainPump : Pump {
    @Info { owner = "pete"; }
}
----

The page of `mainPump` shows a table titled Info with the rows owner = pete
and count = 3.

== sysml-value

Inline macro. Replaced by the value of an attribute. The target names a
feature, read with the page's element as its subject, so it can be:

* an attribute of the page's element: `mass`, or a path such as
  `motor.power`;
* an attribute of another element, by qualified name
  (`Values::custom::count`) or by a name relative to the page's element
  (`custom::count`, `custom.count`);
* a quoted name, which may contain spaces: `'rated power'`.

The target is a name, not an expression: operators, literals and calls
(`count*2`, `count<5`, `5`) fail the macro (<<failures>>). To show a computed
value, give it an attribute in the model (`attribute doubled = count*2;`) and
name that attribute.

The target cannot contain a space outside quotes or a `[`, so literal
quantities such as `10 [kg]` cannot be written in it. A target is required:
`sysml-value:[]` is left as plain text.

The value is evaluated by OpenSysML with the page's element as the subject,
so it is the element's own value, the value of a redefinition
(`attribute :>> mass = 7.5 [kg];`), or the one it gets from its definition
(`attribute mass : ISQ::MassValue default 5 [kg];` on a `part def`).
An attribute's value expression in the model is computed: `10 [km/h] * 2` gives `5.555555555555555 m/s`, since
the engine computes in SI base units.

* A quantity is shown as its magnitude and unit symbol: `5 kg`, `90 km/h`,
  `2.5 m³⋅s⁻¹`.
* A string is shown without quotes, a boolean as `true` or `false`, an
  enumeration literal as written: `Level::low`.
* An attribute with no value is shown as `(no value)`.
* A composite value, one made of attributes of its own (an attribute typed by
  an attribute def with attributes, such as `attribute position : Position;`),
  has no single value to show. It is shown as `[composite]`, and the tool
  prints a warning naming the page and the macro: one per page, however
  often the macro appears there.

Syntax:: `sysml-value:<feature>[]` or
`sysml-value:[<element>::]@<metadata>::<attribute>[]`
Attributes:: none

An attribute the element does not have fails the macro (<<failures>>).

Example:

[source,sysml]
----
part def Pump {
    rep language "asciidoc"
        /* The pump weighs sysml-value:mass[]. */
    attribute mass : ISQ::MassValue default 5 [kg];
}
part mainPump : Pump {
    attribute :>> mass = 7.5 [kg];
}
part sparePump : Pump;
----

The page of `mainPump` reads "The pump weighs 7.5 kg." The page of
`sparePump` reads "The pump weighs 5 kg."

=== Metadata values

A target `@<metadata>::<attribute>` gives the value of an attribute of
metadata applied to the page's element, so metadata values can go into a
table you write yourself, next to rows of your own. Put an element before
the `@` for another element's metadata: `wing::@m::owner`. The value is the
one `sysml-metadata-table` shows: the one the element binds, else the
metadata def's default, written as in the model (`"Petr"` as `Petr`,
`9.5 [kg]` as written, not formatted), else `(no value)`.

[source,sysml]
----
metadata def m {
    attribute owner : String default "nobody";
    attribute reviewed : Boolean default false;
}
part wing {
    @m { owner = "Petr"; }
}
----

[source,asciidoc]
----
[cols="1,1"]
|===
|Owner    | sysml-value:@m::owner[]
|Reviewed | sysml-value:@m::reviewed[]
|Status   | approved
|===
----

On the page of `wing` this gives the rows Owner = Petr, Reviewed = false and
Status = approved. An element without that metadata, an attribute the
metadata def does not have, or a target without an attribute (`@m`) fails the macro (<<failures>>).

== sysml-view

Block macro, on a line of its own. Replaced by a view of the model as
OpenSysML renders it: the view a target names (`sysml-view::interfaces[]`),
named as described in <<naming>>, or, with `sysml-view::[]`, the page's
element, which must then be a view.

* A diagram (an interconnection, tree, state, action view, ...) becomes an
  SVG picture in the page.
* A table view (`render asElementTable`) becomes a table, its first row the
  header.

A title written above the macro (`.Wiring`) titles the picture or the table.
The block has the role `sysml-view`, for styling.

The view is rendered by two programs, which must be installed where the
site is built: OpenSysML's `sysml` command writes the view, and Graphviz's
`dot` lays a diagram out. `sysml-publish` finds them on `PATH`; `-sysml` and
`-dot` name others. Each view is rendered once per run, however many pages
show it. A target that names no view, a page's element that is not a view,
a program that cannot be run and a view `sysml` cannot render fail the macro
(<<failures>>), with the message the program gives.

Syntax:: `sysml-view::[]`, `sysml-view::<view>[]`

Example:

[source,sysml]
----
package Aircraft {
    private import Views::*;
    private import StandardViewDefinitions::*;

    part aircraft {
        rep language "asciidoc"
            /*
            = Aircraft

            .Wiring
            sysml-view::wiring[]
            */
        part engine { out port air; }
        part airConditioner { in port air; }
        interface airDuct connect engine.air to airConditioner.air;

        view wiring {
            expose aircraft;
            render asInterconnectionDiagram;
        }
    }
}
----

The page of `aircraft` shows the interconnection diagram of `engine` and
`airConditioner`, joined by `airDuct`, titled Wiring. The view library
imports (`Views`, `StandardViewDefinitions`) make the `render` kinds known.
