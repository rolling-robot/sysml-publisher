* Definitions
- Model folder :: a directory containing SysML v2 textual notation files
  (=*.sysml=, =*.kerml=), searched recursively.
- AsciiDoc representation :: a =TextualRepresentation= element whose
  =language= is "adoc" or "asciidoc", compared case-insensitively.
- Inherited representation :: an AsciiDoc representation of a usage or
  definition that is owned by an element it specializes, directly or
  transitively. For a usage: its types (definitions), their supertypes, and
  the features it subsets or redefines. For a definition: its supertypes.
- Documented element :: an element that owns at least one AsciiDoc
  representation, or a usage or definition that has at least one inherited
  representation.
- Site folder :: the output directory that receives the generated pages.

* Data source
- DS-1 :: The tool shall obtain model data in one of two ways: by parsing
  the SysML files itself, or from an external service that serves the
  SysML v2 API. For the MVP, the tool shall parse files internally only.
- DS-2 :: The tool shall load every file in the model folder as one model,
  so references across files resolve.
- DS-3 :: (Post-MVP) When an external service is used, the user shall give
  its SysML v2 API base URL and the project to read on the command line.

* Command line
- CLI-1 :: The tool shall be a command-line program whose single function
  is to build the page tree from the model folder into the site folder.
- CLI-2 :: The user may give the model folder path; if omitted, =./model=
  shall be used.
- CLI-3 :: The user may give the site folder path; if omitted, =./site=
  shall be used.
- CLI-4 :: On each run the tool shall replace the site folder's previous
  contents, so no page of a removed element remains.
- CLI-5 :: The tool shall print a summary: number of files and elements
  loaded, and each page written with its path.

* Pages
- PG-1 :: The tool shall generate exactly one page per documented element,
  and one page per ancestor of a documented element (PG-6).
- PG-2 :: A page shall show its title (PG-8), followed by the body of each
  AsciiDoc representation the element owns, in declaration order, and then
  its inherited representations (PG-7).
- PG-3 :: Representation bodies shall be converted to HTML with asciidoctorg.
- PG-4 :: Representations in other languages shall be ignored with a
  warning naming the element and the language.
- PG-5 :: An element without a name that has a page shall be named
  "Unnamed" wherever its name is shown (PG-6, PG-7, MC-8), and the tool
  shall report a warning for it.
- PG-6 :: An element that is not a documented element, but has a documented
  element among its descendants at any depth, shall get an empty page: its
  title, which is the element's name, and no body.
- PG-7 :: On a page, each inherited representation shall be shown
  once, even when reached through several specializations, under a label
  naming the element that owns it, nearest specialization first.
- PG-8 :: The title of a documented element's page shall be the AsciiDoc
  document title (the ~= Title~ header line) that Asciidoctor produces for
  the first of the page's representations, in page order (PG-2), that has
  one, with macros resolved for that page. If none has one, the title shall
  be =untitled-N=, where N numbers such pages among their siblings, starting
  at 1, in tree order. The title shall be used for the page heading, the
  browser tab and the sidebar; page folders do not change (PT-1).
- PG-9 :: When a page's title equals that of an earlier sibling, a suffix
  =-N= shall be added, N being the smallest number from 2 that makes it
  unique among the siblings (=Same=, =Same-2=, =Same-3=).
- PG-10 :: The representation that gives the page its title shall not
  repeat that title in its body; the document titles of the page's other
  representations shall be shown in their bodies.

* Page tree
- PT-1 :: Page locations shall follow the model's containment tree: the page
  of =A::B::C= is =<site>/A/B/C/index.html=.
- PT-2 :: The page of an element shall stay at the same path when unrelated
  parts of the model change.
- PT-3 :: An ancestor that is not a documented element (e.g. a package)
  shall appear in the tree with its empty page (PG-6).
- PT-4 :: A branch with no documented element in it shall not appear.
- PT-5 :: =<site>/index.html= shall be a landing page showing the tree.
- PT-6 :: The page folder of an unnamed element shall be named =unnamed-N=,
  where N numbers the unnamed siblings that have pages, starting at 1, in
  declaration order. These paths are exempt from PT-2: adding or removing an
  unnamed sibling may renumber them.

* Sidebar
- SB-1 :: Every page shall have a sidebar on the right showing the whole
  page tree.
- SB-2 :: Every element in the sidebar shall link to its page.
- SB-3 :: The sidebar shall mark the current page.

* Errors
- ER-1 :: (Post-MVP) If the external service is unreachable, the tool shall
  exit with a nonzero status and a message naming the URL it tried.
- ER-2 :: If the model has errors, the tool shall print each as
  =file:line:col message=, exit with a nonzero status, and write no pages.
- ER-3 :: If the model folder contains no model files, the tool shall exit
  with a nonzero status.
- ER-4 :: If the model has no documented elements, the tool shall warn and
  exit with status 0, writing only the landing page.

* After MVP
- AM-1 :: (First step after the MVP.) The =doc= text of an element shall
  appear on a page only where an AsciiDoc macro in one of the page's
  representations asks for it; the macro shall be replaced by the doc text.
  Without the macro, =doc= comments shall not appear. The macro is
  =sysml-doc= (MC-10).
- AM-2 :: (Not in the MVP, not yet scheduled.) AsciiDoc in a representation
  may link to other elements' pages (=xref:=).

* Macros
Rules every AsciiDoc macro of the tool follows; AM-1 is the first macro.
- MC-1 :: Every macro name shall start with =sysml-= (e.g. =sysml-name=), so
  it cannot collide with Asciidoctor's built-in macros or other extensions.
- MC-2 :: A macro shall be able to refer to the element whose page is being
  rendered ("the page's element"). For an inherited representation (PG-7)
  that is the element of the page showing it, not the element that owns the
  representation.
- MC-3 :: The same representation may render differently on different pages
  (MC-2), so each page shall render its representations itself rather than
  reuse another page's output.
- MC-4 :: Macros shall be written in Go and registered on the asciidoctorg
  instance in one place, the package =internal/macros=, one file per macro
  with its test beside it.
- MC-5 :: The page's element shall be passed to macros as document
  attributes set when a representation is converted (e.g. =sysml-element=,
  the element's id), so macros keep no global state.
- MC-6 :: Every macro shall be documented in =docs/macros.adoc=: its syntax,
  its attributes, and an example.
- MC-7 :: (TBD-8) A macro that cannot do its job, e.g. one naming an element
  the model does not have, shall produce a warning naming the page and the
  macro.
- MC-8 :: The inline macro =sysml-name:[]= shall be replaced by the name of
  the page's element (MC-2), "Unnamed" for an element without a name
  (PG-5). It gives the element's name, not the page title (PG-8), so it can
  be used inside a document title.
- MC-9 :: The inline macro =sysml-qualified-name:[]= shall be replaced by
  the qualified name of the page's element (MC-2), as SysML writes it
  (=Model::'a<b'=). An element without a qualified name, such as an unnamed
  one, gives its positional name (=Model::@2=).
- MC-10 :: The block macro =sysml-doc::[]= shall be replaced by the =doc=
  comments the page's element owns (MC-2), in declaration order, each parsed
  as AsciiDoc. An element without a =doc= gives nothing, and the macro line
  is dropped.
- MC-11 :: The inline macro =sysml-short-name:[]= shall be replaced by the
  short name of the page's element (MC-2), the =a= of =part <a> aaaa=. An
  element without a short name gives nothing.
- MC-12 :: The block macro =sysml-members::[]= shall be replaced by a bullet
  list of the members the page's element owns (MC-2), in declaration order,
  each shown by its name ("Unnamed" for one without) and linked to its page
  when it has one. Annotations (=doc=, comments, representations, metadata
  usages) shall be left out. An element without such members gives nothing.
- MC-13 :: The block macro =sysml-metadata::<metadata def>[]= shall be
  replaced by a table of the attributes of that metadata on the page's
  element (MC-2): one row per attribute of the metadata def and of its
  supertypes (its own first), with the attribute's name and value. The value
  is the one the element binds; where it binds none, the value the metadata
  def gives (a default or a fixed value); where neither exists, "(no value)".
  Strings are shown without quotes, other values as written in the model.
  The metadata def is named by qualified name, or by name when that is
  unique. An element without that metadata gives nothing. A name that is
  missing, unknown or ambiguous shall stop the run with an error naming the
  macro and the page (until TBD-8 decides otherwise).
- MC-14 :: The inline macro =sysml-value:<attribute>[]= shall be replaced
  by the value of that attribute of the page's element (MC-2), the attribute
  named as a SysML expression on the element (=mass=, =motor.power=). The
  value is evaluated: the element's own, a redefinition's, or one from its
  types. A quantity shall be shown as magnitude and unit symbol (=5 kg=,
  =2.5 m³⋅s⁻¹=); a string without quotes; an enumeration literal as written
  (=Level::low=); no value as "(no value)". A composite value (one made of
  attributes of its own) shall be shown as =[composite]=, and the tool shall
  report a warning naming the page and the macro. An attribute the element
  does not have shall stop the run with an error naming the macro and the
  page.
