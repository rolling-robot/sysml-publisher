* Definitions
- Model folder :: a directory containing SysML v2 textual notation files
  (=*.sysml=, =*.kerml=), searched recursively.
- Service :: the external SysML v2 service the model is delegated to
  (DS-1): =sysml-grpc= from OpenSysML today, named by its address (DS-3);
  another SysML v2 service, such as Flexo, later as another Source.
- AsciiDoc representation :: a =TextualRepresentation= element whose
  =language= is "adoc" or "asciidoc", compared case-insensitively.
- Inherited representation :: an AsciiDoc representation of a usage or
  definition that is owned by an element it specializes, directly or
  transitively. For a usage: its types (definitions), their supertypes, and
  the features it subsets or redefines. For a definition: its supertypes.
- Documented element :: an element that owns at least one AsciiDoc
  representation, or a usage or definition that has at least one inherited
  representation.
- Site folder :: the output directory that receives the generated pages.

* Data source
- DS-1 :: The tool shall not parse SysML and shall not hold a parsed model
  in memory: parsing and model storage shall be delegated to the Service.
  The tool shall read the model files only to send their text to the
  service and to locate what it reports. Macro processors and the renderer
  shall hold the elements the information they render is drawn from —
  representations, read properties, the indexes the macros build — never
  the whole model.
- DS-2 :: The tool shall send every file in the model folder to the service
  as the documents of one model, so references across files resolve, each
  document named by its file path. Hidden files and folders (names
  starting with =.=, such as editor lock files and =.git=) shall be
  ignored.
- DS-3 :: The user shall name the Service by its address, on the command
  line (CLI-9) or in the configuration file (CFG-6). The tool shall speak
  one service kind through one Source implementation: =sysml-grpc= today;
  another kind, such as Flexo's REST API, shall be addable as another
  Source without changing the rest of the tool.
- DS-4 :: The tool shall read model data the way the SysML v2 API serves
  it: by element queries, reads of one element's properties, and
  expression evaluation, not by exporting the whole model. It shall find
  the page tree by querying for the textual representations, then grow it
  from their owners: the elements that inherit them, and the owners of
  both up to the top of the model.

* Command line
- CLI-1 :: The tool shall be a command-line program whose single function
  is to build the page tree from the model folder into the site folder.
- CLI-2 :: The user may give the model folder path; if omitted, =./model=
  shall be used.
- CLI-3 :: The user may give the site folder path; if omitted, =./site=
  shall be used.
- CLI-4 :: On each run the tool shall replace the site folder's previous
  contents, so no page of a removed element remains.
- CLI-5 :: The tool shall report a summary: number of files and elements
  loaded, and each page written with its path.
- CLI-6 :: Everything the tool reports shall go to stderr as structured log
  records (Go's log/slog): human-readable text by default, JSON with
  =-log-format json=. =-v= shall add debug records giving the duration of
  each stage (parse, query, page tree, each page, render, write), and the
  page tree record shall count the model's queries, element reads and
  cache hits (DS-4). Asciidoctor's own messages about a representation
  shall be records too, at their severity, naming the page's element and
  the model file and line they are about.
- CLI-7 :: Interrupting the tool (Ctrl-C, SIGTERM) shall stop it, write
  nothing, and exit with status 130.
- CLI-8 :: The user may give the command a diagram is laid out with (MC-21):
  =-dot= for Graphviz's =dot=; if omitted, =dot= shall be found on =PATH=.
  It is needed only when a representation uses a =sysml-view= that is a
  diagram: a table view is written from the rendering's rows.
- CLI-9 :: The user shall give the Service's address on the command line:
  =-api ADDR=, spelled as the SysML client dials it (=localhost:50051=,
  =https://sysml.example.com=). The address =local= names no service: it
  says the tool shall start a =sysml-grpc= of its own for the run, use it,
  and stop it after. When neither =-api= nor the configuration file (CFG-6)
  gives an address, the tool shall refuse with a usage error that says to
  start a =sysml-grpc= service and name it.

* Configuration
- CFG-1 :: The tool shall read an optional configuration file in TOML
  format: =sysml-publish.toml= in the working directory, or the file
  =-config= names, which shall exist. When the default file does not exist,
  the tool shall run without it.
- CFG-2 :: The configuration file shall name, in a =source= section, the
  model folder (=dir=, CLI-2) and the Service's address (=api=, CLI-9),
  and, in a =site= section, the site folder (=dir=, CLI-3), the site's
  title (=title=) and the URL the site is published under (=baseURL=). A
  key that is none of these shall be a usage error naming it.
- CFG-3 :: A value given on the command line shall win over the
  configuration file, and the file over the built-in defaults (CLI-2,
  CLI-3).
- CFG-4 :: =site.title= shall be the site's title, shown on the landing
  page, in the sidebar and after the page title in the browser tab. If
  unset, =Model documentation= shall be used.
- CFG-5 :: =site.baseURL= shall be absolute, else a usage error. When it is
  set, every page shall carry =<link rel="canonical" href=…>= naming the
  page's URL under it. Links between pages stay relative (PT-1).
- CFG-6 :: =source.api= shall be the Service's address (CLI-9), read as the
  SysML client dials it; =local= starts one of the run's own, as CLI-9
  says. A flag the user gave wins over it (CFG-3). The Service's bearer
  token is not configured here: the SysML client reads
  =$OPENSYSML_GRPC_TOKEN=.

* Pages
- PG-1 :: The tool shall generate exactly one page per documented element,
  and one page per ancestor of a documented element (PG-6).
- PG-2 :: A page shall show its title (PG-8), followed by the body of each
  AsciiDoc representation the element owns, in declaration order, and then
  its inherited representations (PG-7).
- PG-3 :: Representation bodies shall be converted to HTML with asciidoctorg.
- PG-4 :: Representations in other languages shall be ignored with a
  warning naming the element and the language.
- PG-5 :: An element without a name that has a page shall be named
  "Unnamed" wherever its name is shown (PG-6, PG-7, MC-8), and the tool
  shall report a warning for it.
- PG-6 :: An element that is not a documented element, but has a documented
  element among its descendants at any depth, shall get an empty page: its
  title, which is the element's name, and no body.
- PG-7 :: On a page, each inherited representation shall be shown
  once, even when reached through several specializations, nearest
  specialization first, looking the same as the element's own
  representations: with no label naming the element that owns it.
- PG-8 :: The title of a documented element's page shall be the AsciiDoc
  document title (the ~= Title~ header line) that Asciidoctor produces for
  the first of the page's representations, in page order (PG-2), that has
  one, with macros resolved for that page. If none has one, the title shall
  be =untitled-N=, where N numbers such pages among their siblings, starting
  at 1, in tree order. The title shall be used for the page heading, the
  browser tab and the sidebar; page folders do not change (PT-1).
- PG-9 :: When a page's title equals that of an earlier sibling, a suffix
  =-N= shall be added, N being the smallest number from 2 that makes it
  unique among the siblings (=Same=, =Same-2=, =Same-3=).
- PG-10 :: The representation that gives the page its title shall not
  repeat that title in its body; the document titles of the page's other
  representations shall be shown in their bodies.

* Page tree
- PT-1 :: Page locations shall follow the model's containment tree: the page
  of =A::B::C= is =<site>/A/B/C/index.html=.
- PT-2 :: The page of an element shall stay at the same path when unrelated
  parts of the model change.
- PT-3 :: An ancestor that is not a documented element (e.g. a package)
  shall appear in the tree with its empty page (PG-6).
- PT-4 :: A branch with no documented element in it shall not appear.
- PT-5 :: =<site>/index.html= shall be a landing page showing the tree.
- PT-6 :: The page folder of an unnamed element shall be named =unnamed-N=,
  where N numbers the unnamed siblings that have pages, starting at 1, in
  declaration order. These paths are exempt from PT-2: adding or removing an
  unnamed sibling may renumber them.

* Sidebar
- SB-1 :: Every page shall have a sidebar on the left showing the whole
  page tree.
- SB-2 :: Every element in the sidebar shall link to its page.
- SB-3 :: The sidebar shall mark the current page.
- SB-4 :: Every table with a header row shall be sortable: clicking a header
  cell sorts the table's rows by that column, ascending on the first click,
  descending on the second, and marks the sorted column (=aria-sort= and a
  triangle after the header's text). Sorting happens in the browser over a
  small script the site ships with the stylesheets; a page without it renders
  and reads exactly as before. A column's values are compared as numbers when
  every value in the column is one, and as text (case-insensitive) otherwise;
  a cell with no text sorts after every other value, in either direction.
- SB-5 :: The user may adjust the sidebar's width by dragging a strip at its
  right edge, and the chosen width shall be remembered in the browser and
  applied on every page of the site. A double-click on the strip shall
  restore the default width. The strip is also keyboard-adjustable. The
  adjustment happens in the browser over a small script the site ships with
  the stylesheets; a page without it renders and reads exactly as before,
  with the default width.

* Errors
- ER-1 :: If the Service cannot be reached, does not answer, or does not
  serve a capability the tool needs, the tool shall exit with a nonzero
  status and a message naming the address and, when that is the problem,
  the missing capability. Nothing shall be written.
- ER-2 :: If the model has errors, the tool shall print each as
  =file:line:col message=, exit with a nonzero status, and write no pages.
- ER-3 :: If the model folder contains no model files, the tool shall exit
  with a nonzero status.
- ER-4 :: If the model has no documented elements, the tool shall warn and
  exit with status 0, writing only the landing page.

* After MVP
- AM-1 :: (First step after the MVP.) The =doc= text of an element shall
  appear on a page only where an AsciiDoc macro in one of the page's
  representations asks for it; the macro shall be replaced by the doc text.
  Without the macro, =doc= comments shall not appear. The macro is
  =sysml-doc= (MC-10).
- AM-2 :: (Not in the MVP, not yet scheduled.) AsciiDoc in a representation
  may link to other elements' pages (=xref:=).
- AM-3 :: (Done: MC-21.) The block macro =sysml-view::<view>[]=
  shall be replaced by the named view as rendered by OpenSysML. The view is
  named relative to the page's element (MC-2) or by qualified name.

* Macros
Rules every AsciiDoc macro of the tool follows; AM-1 is the first macro.
- MC-1 :: Every macro name shall start with =sysml-= (e.g. =sysml-name=), so
  it cannot collide with Asciidoctor's built-in macros or other extensions.
- MC-2 :: A macro shall be able to refer to the element whose page is being
  rendered ("the page's element"). For an inherited representation (PG-7)
  that is the element of the page showing it, not the element that owns the
  representation.
- MC-3 :: The same representation may render differently on different pages
  (MC-2), so each page shall render its representations itself rather than
  reuse another page's output.
- MC-4 :: Macros shall be written in Go and registered on the asciidoctorg
  instance in one place, the package =macros=, one file per macro
  with its test beside it.
- MC-5 :: The page's element shall be passed to macros as document
  attributes set when a representation is converted (e.g. =sysml-element=,
  the element's id), so macros keep no global state.
- MC-6 :: Every macro shall be documented in =docs/macros.adoc=: its syntax,
  its attributes, and an example.
- MC-7 :: A macro that cannot do its job, e.g. one naming an element the
  model does not have, shall produce a warning naming the page and the
  macro (MC-19). Warnings shall be reported once per page and macro: a macro
  written more than once on a page, or shown there by more than one
  representation, warns once; each page that shows it warns on its own.
- MC-8 :: The inline macro =sysml-name:[<element>]= shall be replaced by
  an element's name, as declared and without quotes: without a target, the
  name of the page's element (MC-2), "Unnamed" for an element without a name
  (PG-5); with a target, the name of the element it names (MC-15), such as
  =sysml-name:Model::AircraftPart[]=, =sysml-name:ap[]=. A target of the
  form =[<element>::]@<metadata>[::<attribute>]= names metadata applied to
  the page's element (or to =<element>=) and one of its attributes:
  =sysml-name:@m[]= gives the metadata def's name, =sysml-name:@m::owner[]=
  the attribute's name; the element shall carry that metadata, and the
  attribute shall be one of the def's or its supertypes'. It gives the
  element's name, not the page title (PG-8), so it can be used inside a
  document title. A target that names no element, or several, or metadata
  the element does not carry, or an attribute the metadata does not have,
  shall fail the macro (MC-19).
- MC-9 :: The inline macro =sysml-qualified-name:[<element>]= shall be
  replaced by the qualified name of the page's element (MC-2), or of the
  element the target names, read as for =sysml-name= (MC-8, MC-15), as SysML
  writes it (=Model::'a<b'=). An element without a qualified name, such as
  an unnamed one, gives its positional name (=Model::@2=).
- MC-10 :: The block macro =sysml-doc::[<element>][]= shall be replaced by
  the =doc= comments the page's element owns (MC-2), or the element the
  target names (read as for =sysml-name=, MC-8, MC-15), in declaration
  order, each parsed as AsciiDoc; macros in them still describe the page's
  element. An element without a =doc= gives nothing, and the macro line is
  dropped.
- MC-11 :: The inline macro =sysml-short-name:[<element>]= shall be
  replaced by the short name of the page's element (MC-2), or of the element
  the target names (read as for =sysml-name=, MC-8, MC-15), the =a= of
  =part <a> aaaa=. An element without a short name gives nothing.
- MC-12 :: The block macro =sysml-members-list::[<element or kind>][]= shall be
  replaced by a bullet list of the members the page's element owns (MC-2),
  in declaration order, each shown by its name ("Unnamed" for one without)
  and linked to its page when it has one. Annotations (=doc=, comments,
  representations, metadata usages) and multiplicities shall be left out.
  - Without =<element>=, every such member shall be listed, followed by its
    types in parentheses when it has any: =mass (Real)=,
    =both (Sport)=. The types are the ones the API's =type= answers for the
    member: its written typings and the types it gets through subsetting
    and redefinition, with a written type that another written one
    specializes (=Sport :> Wheel=, =part both : Wheel, Sport=) folded away
    as KerML's derived feature type answers it.
  - With =<element>=, only the members that are typed by it, subclass it
    or subset it shall be listed, without types: through typing,
    subclassification or subsetting (redefinition and reference subsetting
    included), directly or through a chain of them (=part spare : Sport=
    with =Sport :> Wheel= is listed for =Wheel=).
  - With an element kind (a SysML metaclass name in any letter case:
    =partUsage=, =InterfaceUsage=), only the members of exactly that
    metaclass shall be listed, without types. The target shall be read as
    an element (MC-15) first, and as a kind only when no element has that
    name.
  - A target that is neither an element nor a kind, or that several
    elements answer to, shall fail the macro (MC-19).
  - An empty list gives nothing.
- MC-13 :: The block macro =sysml-metadata-table::<metadata def>[]= shall be
  replaced by a table of the attributes of that metadata on the page's
  element (MC-2): one row per attribute of the metadata def and of its
  supertypes (its own first), with the attribute's name and value. The value
  is the one the element binds; where it binds none, the value the metadata
  def gives (a default or a fixed value); where neither exists, "(no value)".
  Strings are shown without quotes, other values as written in the model.
  The metadata def is named as MC-15 says, among metadata defs only. An
  element without that metadata gives nothing. A name that is
  missing, unknown or ambiguous shall fail the macro (MC-19).
- MC-14 :: The inline macro =sysml-value:<feature>[]= shall be replaced
  by the value of the feature it names, read with the page's element (MC-2)
  as subject: a feature of the element (=mass=, a chain =motor.power=), a
  qualified name (=Values::custom::count=) or a name relative to the page's
  element (=custom::count=), quoted names included (='rated power'=). The
  target shall name a feature, not an expression: a target with operators,
  literals or calls (=count*2=) shall fail the macro (MC-19). The value is
  evaluated: the element's own, a redefinition's, or one from its types. A quantity shall be shown as magnitude and unit symbol (=5 kg=,
  =2.5 m³⋅s⁻¹=); a string without quotes; an enumeration literal as written
  (=Level::low=); no value as "(no value)". A composite value (one made of
  attributes of its own) shall be shown as =[composite]=, and the tool shall
  report a warning naming the page and the macro. An attribute the element
  does not have shall fail the macro (MC-19).
  A target =[<element>::]@<metadata>::<attribute>= (=@Info::owner=,
  =wing::@m::owner=) shall give the value of that attribute of the metadata
  applied to the element (the page's element when no element is written):
  the value the metadata usage binds, else the metadata def's, as
  =sysml-metadata-table= shows it (MC-13), written as in the model; several
  usages of the same metadata give their values joined by ", ". The element
  and metadata def are named as MC-15 says, the attribute by name or short
  name. An element without that metadata, an unknown attribute, or a target
  naming no attribute (=@Info=) shall fail the macro (MC-19).

- MC-15 :: A macro that names an element shall find it by trying, in turn:
  a qualified name from the top of the model; a name inside the page's
  element, then inside each element around it, outward; the qualified name
  of a standard-library element the model refers to; a plain name only one
  element of the model has. Each segment of a name may be the element's
  name or its short name, quoted or not. When several elements answer in
  the same step, the name is ambiguous.
- MC-16 :: The inline macro =sysml-rep:[<element>][<language>]= shall be
  replaced by the body of the textual representation in =<language>= that
  the element owns: the page's element without a target, else the element
  the target names, read as for =sysml-name= (MC-8, MC-15). The language is
  compared in any letter case; several representations in it are joined in
  declaration order. The body is inserted as plain text, escaped, not read
  as AsciiDoc. Inherited representations do not count. A missing language,
  or an element without a representation in it, shall fail the macro (MC-19).

- MC-17 :: The block macro =sysml-iface-ends::[<element>][]= shall be
  replaced by a bullet list of the ends of an interface or connection: the
  page's element without a target, else the element the target names, read
  as for =sysml-name= (MC-8, MC-15). Each item shall be the feature an end
  connects (=engine.air=), each segment of the feature linked to its page
  when it has one; an end that connects nothing (an interface def's) shows
  its name only. The source end (the end named =source=, as in =connect a to b=
  and =connect (a, b)=) shall come first, the other ends in declaration
  order. An element without ends shall fail the macro (MC-19).
  The attribute =depth= (=[depth=2]= or =[2]=) shall choose how much of the
  connected feature's path is shown: its qualified path (the owners of the
  feature chain's first element, then the chain), cut to its last =depth=
  segments and joined by =::= (1: =air=, 2: =engine::air=), or the whole
  path for =all= (=Model::aircraft::engine::air=), names quoted as in a
  qualified name. A depth longer than the path shows the whole path.
  Without =depth= the chain is shown as written (=engine.air=). A depth that
  is neither a positive number nor =all= shall fail the macro (MC-19).
  The attribute =name= shall say how each segment is named: =short= (the
  default) its short name when it has one, else its name; =long= always the
  name. A value other than =short= or =long= shall fail the macro
  (MC-19).
- MC-18 :: The text of =sysml-name=, =sysml-short-name= and
  =sysml-qualified-name= (MC-8, MC-9, MC-11) shall link to the page of the
  element it describes when that element has a page (PG-1, PG-6), with a
  relative link (PT-1). It shall not link when the element has no page, when
  it is the page's own element (the link would lead back to the same page),
  or when the text is empty (an element without a short name). In a
  document title, the link is kept in the page heading and dropped from the
  browser tab and the sidebar (PG-8). Every link a macro makes to a page
  (these, =sysml-members-list=, =sysml-iface-ends=, =sysml-ifaces=, custom
  macros' links,
  MC-20) shall be an Asciidoctor link written by the output's converter,
  marked with the element it leads to, so that an output whose links are
  not =<a href>= (Confluence's =<ac:link>=) writes its own.
- MC-19 :: A macro that fails (one that cannot do what is written, e.g. it
  names an element the model does not have) shall leave a visible
  placeholder where it is written, showing the macro and the problem, and
  shall report a warning naming the source location (file and line where
  the macro is written in the model), the page and the macro (MC-7). The
  run shall go on and succeed, so every failing macro on every page is
  reported in one run; the rest of the page is rendered as usual. Only an
  interrupted run (CLI-7) stops rendering.
- MC-20 :: Other Go programs shall be able to use the macros (package
  =macros=, without internal packages) and to add AsciiDoc macros of their
  own that behave like the =sysml-*= ones: they read the same model, name
  elements as MC-15 says, link to pages as MC-18 does, show values as
  =sysml-value= does (MC-14), and a failing one leaves a placeholder and a
  warning (MC-19). Names starting with =sysml-= stay reserved for this
  tool's macros (MC-1).
- MC-21 :: The block macro =sysml-view::[<view>][]= (AM-3) shall be
  replaced by the view as OpenSysML renders it, in process through the
  SysML v2 API's render-view operation (TBD-9); Graphviz's =dot= shall lay
  a diagram out. A diagram shall be put in the page as an SVG picture, a
  table view (one the rendering gives as columns and rows, not as a
  diagram) as a table. The target
  names the view as MC-15 says; without a target, the page's element shall
  be the view. A block title written above the macro (=.Title=) shall be
  the picture's or the table's title. Like a link (MC-18), the picture and
  the table shall be Asciidoctor blocks written by the output's converter
  (an image, its SVG in the image's target; a table), marked with the
  view's qualified name, so that an output whose pictures are not =<img>=
  (Confluence's attachments) writes its own. A view shown on several pages shall be rendered once per run.
  A target that names no view, a page's element that is not a view, a
  program that cannot be run and a view the renderer cannot render shall
  fail the macro (MC-19), with the message the renderer gives.
- MC-23 :: The block macro =sysml-ifaces::[<element>][]= shall be replaced by
  a bullet list of the interfaces and connections the target is on: every
  =ConnectionUsage= and =InterfaceUsage= of the whole model whose ends
  reference one of the target's owned ports (=PortUsage= members). Without a
  target the page's element is used, named as MC-15 says. Each item is one
  connection: its name, linked to its page (MC-18) when it has one, then
  = -> = and the distinct part(s) on the other ends — the ends that do not
  reference the target's ports — each the owner of the end's leaf feature,
  linked and joined with =, =. A connection all of whose ends reference the
  target's ports shows the connection alone (an empty right side). A part
  with no owned ports, or with none that any connection references, drops the
  macro line (MC-12). The =name= attribute says how each part is named,
  =short= (the default) using its short name when it has one, =long= always
  its name; a value other than the two fails the macro (MC-19). The model is
  searched once, a reverse index of ports to connections built on first use
  and shared by every page (MC-3). A target naming no element, or that is
  not part-like, fails the macro (MC-19).
- MC-24 :: The block macro =sysml-catalog::[]= shall be replaced, on a
  view's page, by a table of that view's exposed elements: one row per
  element of the view's exposed tree that carries the view's filter
  metadata. The exposed root and the filter shall come solely from the
  page's view element (its =expose … / filter …=), never from a root or
  filter attribute of the macro. A =*+= expose names the root's direct
  members, a =**= expose its whole subtree (recursively, cycle-safe,
  skipping library elements). A row is an exposed element that owns a
  metadata usage of the filter def; its Name cell is the element's name,
  linked to its page (MC-18) when it has one, and the remaining cells are
  the values (MC-13: bound, else the def's default/fixed, else absent) of
  the metadata def's attributes. The columns are the first row's metadata
  def attributes, each labelled by the (redefined) attribute's representation
  body, else its name, ordered by the attribute's =order= literal
  (ascending, the Name column first). A page's element that is not a view,
  a view with no expose or no filter, or an unresolvable exposed root or
  filter def fails the macro (MC-19). An exposed tree with no element
  carrying the filter metadata drops the macro line (MC-12).
- MC-25 :: The block macro =sysml-fig::[<element>][]= shall be replaced, when
  the target is an interface (an =InterfaceUsage=; without a target the
  page's element is used, named as MC-15 says), by a figure of that
  interface: a Mermaid flowchart the site draws in the browser with the
  vendored =mermaid.min.js=, in the look of OpenSysML's Mermaid
  interconnection form. The figure shows, and nothing else: one box per part
  of the figure's tree — the ends' deepest common ancestor, the owner of
  each end's leaf feature, and every part between, nested as the model nests
  them; the common ancestor is the figure's frame and drawn whatever it is,
  a package included, while a package further down a chain is not drawn —
  and a stadium node per end feature inside its owner's box. One edge per
  pair of ends joins the end features, drawn as the thick ==== connection
  line of OpenSysML's Mermaid form; an edge whose two ends are the same
  feature is not drawn. The figure's elements are found in the model the way
  MC-15 and MC-23 read it; the figure draws exactly what the ends' chains
  pass through, unnamed elements included. The Mermaid text is written by
  this tool; its style constants are copied from OpenSysML's Mermaid writer
  (§10-8). A target that names no element fails the macro (MC-19); a
